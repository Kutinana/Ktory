# Ktory 待解决的工程问题

更新日期：2026-10-22

本文只记录尚未落实的产品目标与工程边界。产品目标见[设计宪章](ktory-design-charter.md)及 [scope](ktory-scope_v1.md)，已确认语法和运行协议以[实现规格](ktory-implementation_v1.md)为准，验证与交付见[工作流](ktory-workflow.md)。已定案的语义直接维护在规范中，不在此保留旧候选。

## 1. 共享呈现、资源绑定与信号交接

| 主题 | 已确认约束 | 待工程决定 |
| --- | --- | --- |
| 默认呈现 | 文件内 speaker 默认修饰符及逐句整组覆盖已实现；表情为本句 → 适用默认 → 不展示，不继承上句局部状态 | 跨文件共享定义、引用与存储结构；缺失／错误资源诊断；未来是否需要明确取消默认值 |
| 演出绑定 | 编辑器选择资源、绑定对象与脚本声明；同类内容复用一次能力接入 | 资源／节点配置形式、编辑器交互、通用处理器与项目扩展边界 |
| 信号交接 | 脚本显式声明依赖，宿主判定并报告真实事件；包括无对白段落 | 等待记录承载模块；对应本次播放，隔离同名演出、旧会话、重复与迟到通知；完成／取消／失败及订阅清理 |
| 输入与时间组合 | 不隐式阻塞所有演出，保持现行 wait／next／duration | 信号依赖与点击确认、自动推进、快显、跳过、中途打断及恢复的组合；保持单一推进责任 |
| 独立试读 | 不模拟未知外部状态，不把跳过演出当成真实信号发生 | 新信号依赖的试读策略与标示，须在支持声明前明确 |
| 容器扩展 | 未知容器目前警告后按 choice 降级 | 通用 Handler 注册／执行扩展及 SDK 分工，不能把降级视为扩展已交付 |

省略表情须形成实际不展示的结果，由宿主清除旧表情；该规则不推广到持续播放的 BGM。当前不增加取消默认值语法。未来信号依赖先定义可观察行为与生命周期，再确定语法、API 和承载模块；Main 的 awaitTrack 是等待辅助执行结束，不是外部演出完成信号。

建议按跨文件共享呈现 → 绑定与完成信号 → 中途节点推进，用[工作流中的代表性场景](ktory-workflow.md#新增目标的代表性验证场景待落实)验证重复配置和专用代码是否减少。此顺序不扩大第一阶段验收范围。

## 2. 明确延期的范围

- 外部文件须使用显式 URL；URL 格式与各引擎加载协议待设计。Core 不猜测 source 字符串是不是资源路径，也不枚举宿主全部资源。
- 按当前情况选择剧情、交还玩家操作后继续原剧情的目标已确认；触发、冲突、取消、跨场景及存档范围另定。
- 持久化存读档、逐句恢复、配音系统、翻译提取回填与 Timeline 深度集成不进入当前第一阶段验收。

真实 Unity 呈现、媒体同步、资源绑定及生命周期须在固定源提交／包提交上另验。本机 Core、桥接、Reader 的结果不能替代实机证据。
