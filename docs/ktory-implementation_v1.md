### 1.2 第一阶段交付范围

1. **核心解析器与剧情调度器（Core Parser & Sequencer）**：对白、分支选择、循环调查、调用栈、会话内叙事记录（访问历史）。
2. **多语言同文件维护**：同一 `.ktr` 脚本内多语言变体解析与请求缺译时的回退输出。
3. **独立试读工具（Standalone Runner）**：不依赖 Unity 环境，支持语言切换与未知外部条件忽略。
4. **Unity 基础接入组件**：基础对话框与立绘驱动，满足阶段性验收。

> **阶段非目标（Explicit Out of Scope）**：
> 第一阶段不包含持久化存读档、配音系统、翻译文本自动提取/回填工具、Timeline 深度绑定或核心内部异步演出等待。
> 这是当前阶段范围，不是永久禁止脚本声明信号依赖。§1.4 的新增目标不自动扩大上述验收基线。

### 1.3 当前技术基线的架构边界与原则

1. **单向离散步进（Step-Driven）**：核心在同一会话中维护唯一 Main 和零个或多个自动辅助播放头，各自按源码顺序执行。章节本身不分主辅，身份属于播放头；核心不读取墙上时钟、不执行视听演出。
2. **文本就绪下放，执行门控由 Core 持有**：
   - 文本呈现进度（打字机、渐显、即时显示）、快显控制（Fast-forward）、文本就绪判定（`canAdvance`）**完全由接入层持有**。
   - 核心不维护文本门禁锁，不记录打字机完成百分比，亦不等待文本就绪回调。
3. **外部状态解耦**：核心维护剧情位置、栈、循环、实例／时钟和会话消耗历史；外部背包、角色属性等由宿主系统驱动，不侵入核心内部状态。
4. **术语与保证边界**：拍是逻辑停止点，不承诺外部动作完成；Forward-Only 不禁止循环和向后跳转，表示不自动撤销外部副作用。原生富文本与项目表达式方言不保证跨渲染器或宿主自动兼容。
5. **验证边界**：用户已在另一设备接入 Unity。当前设备优先验证核心、呈现策略及桥接，远端反馈绑定源提交与包提交。Core 单测、Web 运行、Unity 导入及实际播放是分别记录的证据。

## 2. 词法与语法规范（Syntax Specification）

### 2.1 基础概念：锚点与修饰符（Anchor-Decorator Model）

脚本由离散的执行节点构成，词法上分为两类：
* **锚点（Anchor）**：显式声明一个执行节点。包括文本对白行、旁白行、指令拍行（`#`）以及容器子项行（`*` / `+`）。
* **修饰符（Decorator）**：以 `.` 开头，严格吸附至离它最近的上方锚点，作为该节点的元数据。修饰符可链式书写或缩进换行书写。
* **悬空修饰符**：所属块中没有上方锚点时，报告带源码行号的语法错误并停止加载；不得静默丢弃、吸附到下一句，或借用另一命名节／分支的锚点。文件首行的 `.effect` 属于此错误。

#### 修饰符参数规则
* **无参等价性**：`.tag` 与 `.tag()` 在解析层完全等价，均传递无参修饰符。
* **零值独立性**：通用宿主标签 `.tag(0)` 与无参不同。内建参数采用完整具名形式，显式零值也不等于省略。
* **内建完整参数**：`clock(name?, source?)`、`defaultClock(name)`、`resetClock(name?)`、`track(source, name?)`、`await()`、`stopTrack(name)`、`awaitTrack(name)`、`at(value, clock?)`、`wait(seconds?)`、`next(seconds?)`、`duration(seconds)`、`skippable(enabled?, seconds?)`、`loop(count?)`。`?` 仅在本表表示可省略参数，脚本不写问号；已提供的参数必须写名称。内建位置参数本版不支持，重复／未知参数与类型错误给源码诊断；不禁用未知宿主标签的位置参数。
* **可选不等于空字符串**：省略 name 表示匿名或当前默认，依操作而定；显式空 name 无效。只有 clock 的 source 空串等价于省略 source。
* **数值参数**：wait／next／duration／skippable 的 seconds 为有限非负数；duration 必须指定 seconds。at 的 value 可为任意有限数；loop 的 count 为 int 范围整数，<= 1 保持既有单次执行语义。

### 2.2 节点类型与书写规则

#### 2.2.1 文本与对白锚点（Text / Dialogue Anchor）
```ktory
说话人: 文本内容
: 匿名旁白内容
```
* **首冒号规则**：词法解析仅以行内未被纯文本围栏包围的首个半角 `:` 或全角 `：` 分割说话人与正文。其后出现的冒号均视为文本内容。
* **匿名旁白**：冒号前为空白或无说话人时，收敛为匿名文本节点（`Speaker = null`）。
* **行内富文本**：支持行内转译（`*斜体*`, `**粗体**`, `~~删除线~~`, `[基准]{注音}`）及原生引擎标签直通（如 `<color=red>`）。禁止使用块级 Markdown（如标题 `#`、列表 `-`、多行代码块）。

#### 2.2.1.1 纯文本围栏（2026-10-18，已确认并实现）

为在对白中直接显示 `.wait`、注释、格式示例等保留语法，使用三个或更多连续 ASCII 单引号包围纯文本片段。可内嵌在普通正文中，也可跨多行；围栏不是新的执行节点。

```ktory
爱丽丝: 我想写'''.wait'''，然后继续。 .wait(seconds=1)
爱丽丝:
  @zh: '''
    .wait
    // 这也是正文
    <b>**不会变成粗体**</b>
  '''
  @en: Text with '''.wait''' inside.
  .next(seconds=1)
: ''''这里可以直接显示 ''' 三个单引号''''
: ''''
  '''
''''
```

- 开始围栏取当前位置连续单引号的完整长度 `N >= 3`；结束围栏必须是长度恰好为 `N` 的完整引号串。较短／较长的串均为正文，不嵌套解析。选择比内容中连续单引号更长的围栏；需要只显示引号时，使用多行区块以免内容与边界连成一串。中文 `‘`、`’` 不参与围栏。
- 围栏内所有字符按字面保留，不提取修饰符、注释、控制流、节声明或旧 lane 字样、语言标签，也不执行 Markdown、Ruby、反斜杠去转义或原生富文本标签。围栏外继续遵循原语法；正文中真正的行尾 tag 仍要求空白边界及完整尾部序列。指令参数和 speaker 声明仍使用原有引号规则。
- 单行片段保留首尾空白。多行区块的开始围栏后若只有水平空白再换行，则移除这条排版行；结束围栏前若该行只有水平空白，也移除这条排版行。区块非空正文行的最小公共缩进被移除，tab 仍按两列计算，保留内部相对缩进、空行及行尾空格；换行统一为 `\n`。开始围栏后同一行已有正文的跨行片段保持原有内部空白。
- 整个对白仍是一拍，不因区块换行而增加拍。围栏内的退缩进不终止当前分支；围栏外后续语句继续按自身物理源码行和缩进解析。
- `@locale:` 在围栏外标识每个语言版本，各版本可以混用普通文本和纯文本片段；围栏内的 `@locale:` 仅是文字。主语言回退及副语言精确取译文的规则不变，修饰符属于整拍，切语言不重放副作用。选项标签的 `[...]` 内也可包含围栏，围栏中的方括号不结束标签。
- 未闭合围栏阻止加载，并报告开始围栏的物理行／列，Linter 为 `KTR_E012`。不能静默把后续剧情猜作普通正文。

该决定服务正文保真与语法示例书写，对应 C04／C06／C08。Core 维护片段边界和实际语言，宿主负责按字面渲染纯文本片段。Reader／VS Code 共用渲染与唯一 TextMate grammar；Unity 宿主的真实显示仍需单独验收。

#### 2.2.2 指令拍与空拍（Directive Anchor）

普通独立 `#`（下方无容器子项）默认自动执行，按顺序派发标签后继续；裸 `#` 同样不要求点击。Main 的 `:` 文本／输入拍默认手动。空 `:` 不输出新文字，但它是本头新的一句：进入时结束前句显示，再等待有效输入；不停止 BGM 等持续资源。可以在空 `:` 上附标签。

```ktory
#.camera_shake(0.5)             // 宿主标签可保留位置参数；派发后默认继续
: .camera_shake(0.5)            // Main 派发后等待有效 advance
#.wait(seconds=3)              // 3 秒后默认自动继续
: .wait(seconds=3)             // 3 秒解除限制后，仍等新输入
#.wait(seconds=3).next(seconds=5) // 3 秒后可点击，5 秒自动
```

无文本拍的呈现计时从进入起算。`wait` 没有自行启用自动，第一种自动性来自 # 的默认策略。普通动作派发不等待动画／音乐完成，也不保证相邻动作间隔一帧。choice 等容器依 §2.2.3／§3.2，不能套用“所有 # 都自动”的说法。辅助不因 `:`、裸 #、wait 或 next 获得输入或呈现等待。

#### 2.2.3 容器与子项判定（Container & Items）
解析器**严格根据缩进及其下方是否存在归属子项**判定 `#` 行是容器还是独立指令拍：
* **容器判定**：若 `#` 锚点下方存在缩进的 `*` 或 `+` 子项，则解析为容器节点。
* **名称解耦**：`#` 后的标识符（如 `#choice`）仅作为 Handler 查找名称。`#choice` 不是解析器保留关键字。配套 SDK 默认将 `ChoiceHandler` 绑定至名称 `choice`。
* **子项标记与多语言规范**：
  * 单语言书写：`* [选项文本]`（一次性项，有效提交后置为已消耗）或 `+ [选项文本]`（持久可重复项）。
  * 多语言标准写法（两阶段缩进模型）：
    ```ktory
    #choice
      .tag(param)

      * [@zh: "向爱丽丝搭话"]
        [@en: "Talk to Alice"]
        .tag(param)

        alice:
          @zh: 我们必须尽快离开！
          @en: We have to leave!
          .tag(param)
    ```
  * **两阶段封闭规则（Option Head -> Option Body）**：
    1. **选项头部（Head）**：紧随 `*` / `+` 缩进一级的 `[@locale: ...]` 文本标签与选项修饰符 `.tag` 均属于该选项本身。
    2. **分支执行体（Body）**：一旦出现分支语句锚点（对白 `speaker:`、旁白 `: `、系统指令 `#`、跳转 `->`、调用 `=>`），选项头部立即强制封闭，进入分支执行序列。
    3. **编译期防呆报错**：在分支执行语句之后，同级缩进严禁再出现 `[@locale: ...]`。一旦发现，解析器直接报编译期语法错误（Fail-Fast），绝不模糊猜测其归属。
* **Handler 缺失回退机制**：
  * 遇到未注册对应 Handler 的容器，解析器与运行时不得崩溃或挂死。
  * 运行时发出包含原容器名称与源码位置的 `Warning`（严禁静默吞掉）。
  * 降级回退至基础 `choice` 行为展示子项并等待输入。若子项全部不可选或无子项，自然越过该容器。

### 2.3 缩进排版与语法诊断标准

缩进在 Ktory 中具备结构界定语义：
1. **容器子项**：必须相对容器声明行进行缩进。
2. **内联分支正文**：必须相对其所属的子项行进行更深层缩进。
3. **退出界定**：行首缩进退回至父级层级时，显式终结当前子块或容器。
4. **诊断原则**：
   - **Warning（可恢复）**：排版层级的微小偏差但能通过上下文无歧义推断归属时，报出 Warning，交由代码格式化器规范化。
   - **Error（结构歧义）**：缩进导致结构归属不明或产生分支歧义时，必须立即报告语法错误，严禁解析器隐式猜测。

### 2.4 节（Section）与根节（Root Section）

```ktory
// 根节正文（Root Section）
主角: 故事从这里开始。

=== Sub_Plot ===
  // 命名节正文：必须比声明行缩进
  艾莉丝: 这是支线内容。
  -> return

// 缩进退回顶格，恢复根节
主角: 支线之后的主干故事。
```

* **命名节**：`=== Label ===` 声明命名节。其内部正文必须相对声明行缩进；缩进退回该声明层级即宣告该节结束。
* **根节执行流**：未包含在任何命名节的代码构成根节。根节按源码线性顺序执行，**遇到命名节声明行时自动跳过其整个正文**，继续执行其后的根节节点。
* **进入方式**：命名节可由显式跳转（`-> Label`）、调用（`=> Label`）、Main 的 `#.track(source="Label")` 或宿主指定入口进入。章节角色中立，同一节可同时被多个播放头执行。
* **默认入口**：`Start()` 只从根节开始；根节为空时直接完成，不自动进入第一个命名节。声明后未缩进的正文属于根节，不能按旧兼容行为吞入命名节。

### 2.5 多语言声明与回退规则

以下至 §2.5.3 规定主语言解析和声明规则；副语言精确选取与输出 API 见 §2.5.4。

| 特性 | 规范定义 |
| :--- | :--- |
| **文件组织** | 同一脚本文件内通过 `@locale:` 维护文本多语言变体；通过 `@speaker` 维护说话人映射；允许单语言直接书写。 |
| **默认语言** | 脚本可通过文件级元属性指定 `@defaultLang: <locale>`。若显式指定，无修饰正文归入该默认语言；若未指定且全文包含 `@locale` 变体，为保持向后兼容缺省为 `zh`；若未指定且全文无任何 `@locale` 多语言声明，脚本视为未本地化（Unlocalized）单语言剧本，默认语言为 `null`，正文与选项的实际语言 `ActualLanguage` 均输出 `null`，不假定为特定语言。 |
| **缺译回退** | 请求语言缺失时先回退 `defaultLang`；两者均无有效文本时，按已有译文顺序选取第一个有效译文，并发出包含源码位置的 `Warning`。正文、选项及已声明说话人的名字分别执行此规则。 |
| **语言标签透传** | 正文与选项通过各自 `ActualLanguage`，已声明说话人通过 `SpeakerActualLanguage` 报告实际语言；保留请求语言，不将第三语言或默认语言伪标为请求语言。 |
| **即时热切换** | 运行时切换语言时（`SetLanguage`），当前暂停节点的文本、说话人及选项内容即时重算更新，无多余副作用。 |

第三语言回退使用该节点已有有效译文的顺序，不自动合成占位文本。请求或默认语言能够正常命中时，不因常规回退额外要求警告。已声明说话人若没有任何非空显示名，例如 `@speaker alice:`，属于声明错误，须在加载时报告行号并停止。正文和选项的空声明不由本次决定新增统一规则。本条不改变未声明说话人按字面输出的规则，也不将其字面量伪报成某种本地化语言。

#### 2.5.1 说话人多语言声明（Speaker Localization）

说话人声明定义跨对白复用的本地化名字与反查别名，并可在缩进块内声明默认修饰符（§2.5.3）。简短 ID 也是别名，不会自动解析为立绘、语音或完整游戏角色；修饰符的资源解释由宿主决定：

```ktory
// 方式一：无显式 ID，各语言名互为反查别名（推荐值加引号）
@speaker: zh="爱丽丝" | en="Alice" | ja="アリス"

// 方式二：指定简短 ID（如代号/拼音），该 ID 与各语言名均纳入反查别名表
@speaker alice: zh="爱丽丝" | en="Alice" | ja="アリス"
```

1. **别名集合与双向反查（Alias Set & Reverse Lookup）**：
   - 方式一中，`爱丽丝`、`Alice`、`アリス` 共同构成该角色的反查别名。
   - 方式二中，`alice`、`爱丽丝`、`Alice`、`アリス` 均指向同一说话人实体。
   - 剧本对白冒号前无论书写 `alice:`、`Alice:` 还是 `爱丽丝:`，均解析绑定至该实体，并根据运行时请求语言输出对应的本地化显示名称。
2. **严格大小写敏感（Case-Sensitive）**：
   - 反查别名采用严格大小写匹配。`alice`、`Alice` 与 `ALICE` 视为不同别名。
3. **零容忍冲突检查（Strict Error on Duplicate/Collision）**：
   - **禁止重复声明**：同一别名在作用域内严禁被重复声明。若出现重复声明或跨声明别名冲突，编译期直接抛出 `Compile Error` 阻断。
4. **未声明角色降级（Fallback）**：
   - 若某对白说话人未在任何 `@speaker` 中声明，系统不阻断执行，各语言环境下均原样输出该字符串字面量。

#### 2.5.2 对白与选项文本多语言

```ktory
// 对白多语言
alice:
  @zh: 你好，旅行者。
  @en: Hello, traveler.
  .emotion(smile)

// 选项多语言（见 §2.2.3 两阶段缩进模型）
* [@zh: "向爱丽丝搭话"]
  [@en: "Talk to Alice"]
  .tag(param)
```

#### 2.5.3 Speaker 默认修饰符（2026-09-27，已确认并实现）

```ktory
@speaker alice: zh="爱丽丝" | en="Alice"
  .portrait(normal).voice(soft)

alice: 使用默认值。
alice: 本句改变表情。 .portrait(happy)
Alice: 这里恢复 normal。
```

- 默认区必须缩进在 speaker 声明下，只接受完整修饰符序列，不产生执行拍；名字声明仍须至少有一个非空显示名。
- 定义在当前文件内有效，不依赖声明出现顺序；同一 speaker 的 ID 与全部别名共用默认值，适用于根节、命名节和选项内联分支中的对白。旁白、指令拍和选项项不继承 speaker 默认值。
- 每句独立解析。本句出现某个名称时，按不区分大小写的名称，替换默认区该名称的整组修饰符；不按参数逐项合并。本句重复同名修饰符保留全部及其顺序。
- 最终顺序是未被覆盖的默认修饰符（声明顺序），再接本句修饰符（源码顺序）。解析后 `TextStep.Tags` 及输出 `TextPayload.Tags` 都是本句有效列表；`SpeakerDefinition.DefaultTags` 保存声明列表。
- 普通宿主及呈现修饰符不设资源允许名单，等同逐句显式书写；时钟／at／轨道控制不能作为 speaker 默认，须在执行位置显式声明。`.wait/.next/.loop` 等保留原有语义；默认 `.sfx(bell)` 若被宿主解释为播放音效，就会在每句进入时播放一次。作者负责选择适合重复使用的默认修饰符。
- 切语言只刷新文本和名字，不再次派发默认或局部修饰符。下一句重新应用默认值，上一句局部值不会进入下一句列表。
- 本轮不引入取消默认值语法；`.-portrait` 不是合法写法。跨文件共享、资源名有效性、编辑器绑定和信号依赖仍未实现。
- 对立绘／表情，宿主读取当前拍的完整有效列表，并清除当前拍没有定义且没有默认值的相应显示；不能只监听“设置新表情”的事件而残留旧显示。Ktory 不会把任意省略的修饰符解释成停止外部动作，尤其不隐式停止 BGM。

#### 2.5.4 主／副语言结构化输出（2026-09-29）

文件 `defaultLang` 负责未标注文本归属与主语言缺译回退；运行时 `RequestedLanguage` 是主语言，`SecondaryLanguage` 是可选副语言。`Start(entryLabel, requestedLocale, secondaryLocale)` 可初始化两者，`SetLanguage(locale)` 仅切换主语言，`SetSecondaryLanguage(locale)` 仅切换副语言，`SetLanguageOutput(primaryLocale, secondaryLocale)` 同时设置两者；副语言为 null 或空白时关闭。

- `TextPayload.Text`、可空的 `TextPayload.SpeakerName` 与 `ChoiceOption.Text` 分别为 `LocalizedTextOutput`，含 `Primary` 和可空的 `Secondary`。每份值均报告 `Content`、`RequestedLanguage`、`ActualLanguage`。旧 `Content`／`Speaker`／`Label` 及实际语言属性映射主语言，节点与选项身份保持单份。
- 主语言继续按 §2.5 回退。**副语言只取所请求语言的有效译文，不回退**；无译文时该字段 `Secondary == null`。文件有明确默认语言时，未标注值可作为该默认语言的精确译文；未本地化值和未声明说话人的字面名字不伪造副语言。
- 按字段比较语言：副语言请求与该字段主语言的 `ActualLanguage` 相同则省略；两种语言文字偶然相同仍保留。正文与名字独立，因此正文省略副语言时名字仍可有副语言。没有地域语言自动回退链。
- 开关或切换语言只刷新尚保留的显示内容及 Main 当前文本／选择的语言字段，不移动 PC、重置调用／循环、重新求值选项条件、消费选项或派发标签；保持呈现和选项身份。刷新范围包括已结束辅助和自然结束会话的保留内容，不限于 `GetActivePresentations()` 的输入快照；已释放显示不重新出现。renderer 自行决定副语言是否显示及布局，不输出预拼接双语字符串。
- 默认阅读时间仅依据主语言的实际文字及语言。副语言刷新不改变打字机进度、固定／预估计时或已解除的限制。接入层用 `RefreshSecondaryLanguage()`，多轨控制器用 `RefreshLanguage(secondaryOnly: true)` 通知重绘；主语言切换继续使用 §2.6 的刷新规则。

### 2.6 表现层修饰符标准约定

本节的推进策略仅用于 Main。玩家或自动策略提出 trial，接入策略根据打印、快显和最低停留决定是否向 Core 提交 advance；Core 不读取打印进度。辅助输出后直接继续至下一 Core 门控或结束，不等待显示完成，不应用 wait／next 或隐含阅读时长。duration 仍可作用于辅助显示。

| 完整语法 | 起点与标准行为 |
| --- | --- |
| `.skippable(enabled=false, seconds=1)` | 仅限制文字显示中的快显；缺省 enabled 为 true，enabled=false 且省略 seconds 时整句打印期间不可快显。受限点击丢弃，不排队；显示完成后的推进不受它限制 |
| `.next(seconds=2)` | 全文显示完成后 2 秒请求自动 advance；省略 seconds 为 0。wait 已解除时，有效人工输入可提前推进并使旧自动请求失效 |
| `.wait(seconds=2)` | 全文显示完成后最低停留 2 秒，期间人工输入丢弃；到期只解除限制，是否自动继续取决于 next／AUTO／# 默认自动或宿主策略 |
| `.wait()` | 最低停留按当前主语言实际输出的阅读估时计算；副语言不参与估时 |
| `.duration(seconds=3)` | 与 wait 同起点、同秒计时口径，3 秒后显示内容过期，由宿主隐藏／淡出；完全不限制 advance，next 和默认 AUTO 都不等它或淡出完成 |

- 文本的 next／wait／duration 从全文显示完成起算；没有文本显示阶段的拍从进入起算。允许快显时，该次点击只快显，完成时开始句后计时，不同时推进。
- wait(s) 与 next(t) 同起点并行，自动提交时点为 max(s,t)。例如 `.wait(seconds=5).next(seconds=2)` 在 5 秒自动继续；自动条件在 2 秒到期后保持到期状态，不能因一次 trial 被 wait 阻挡而永远丢失。人工点击不缓存。
- 独立 # 默认自动时点为 0，显式 next 替代该默认时点，wait 提供最低限制。Main 空 `:` 默认手动，next／AUTO 可改其策略。
- 每个播放头一次只播放一条语句：后一句真正进入时，前一句退出并消失，不论是否使用同一显示位置。duration 是不阻滞 advance 的显示等待；有效 advance 可提前进入下一句，不为旧句保留独立寿命。省略 duration 时，当前显示留到本头后一句进入；等待下一句的 at 时尚未进入新句，前句仍可按自身寿命保留。EOF／stop 没有下一句，末句可继续显示。duration 到期只隐藏，不产生 advance；wait 不隐含隐藏。
- duration 复用 wait 的增量／暂停计时口径，不取 at 来源值计时；该来源可为任意数值。迟到的 at 仍正常执行，不按“过期文本”省略输出或副作用。
- 固定计时不因语言刷新重启；Main 阅读估时按新主语言重算并保留完成比例，最低停留已解除不重新锁定。副语言刷新不改变打印或计时。
- 旧 next、duration 或淡出回调捕获原内容身份；不能推进新句或清掉新显示。显示寿命不等于推进授权，执行停止不要求立刻清屏。

### 2.7 区域自动播放（`#AUTO` / `#AUTO_END`）

用于定义由脚本完全掌控节拍、无需玩家交互的自动化演出区间。

**作用域**：AUTO 只安排 Main 呈现推进；辅助始终直接执行，AUTO／AUTO_END 不改变其权限，也不引入 wait／next 等待。Main 的以下词法作用域与调用不继承规则保留；默认时钟引用另按 §2.8，不随 AUTO 作用域恢复。

1. **宏标记行为**：
   - `#AUTO`：进入区域即刻启用自动步进策略，本身不产生可观察的点击停顿。
   - `#AUTO_END`：离开区域时穿过该行，随后关闭自动模式，不产生多余空拍。
2. **步进规则**：
   - 区域内节点若未声明停留，默认在呈现可放行时立即推入下一步。
   - 声明 `#AUTO.wait` 时，区域内有文本的拍默认应用该语言的预估阅读时间。
   - 局部修饰符优先级高于区域默认值：局部 `.wait(seconds=3)` 覆盖为 3 秒的最低停留；局部 `.wait(seconds=0)` 覆盖为 0 秒。这里的自动推进来自 AUTO 区域，非 `.wait` 本身；若同时声明 `.next(seconds=t)`，与局部 `.wait` 按 §2.6 并行组合，忽略区域默认时长。
3. **源码作用域（Lexical Scope）**：
   - AUTO 模式严格依源码位置生效，**不随调用栈向外部继承**。
   - 从 `#AUTO` 块调用外部命名节（如 `=> Sub_External`），子过程中不继承 AUTO；子过程返回原区域后，继续遵循原区域 AUTO 规则。

### 2.8 时钟身份、默认引用与进入门控

```ktory
#.clock()
: 本播放头默认钟达到 2 后进入。 .at(value=2).next(seconds=1)
#.resetClock()
: 默认钟重置后达到 1 时进入。 .at(value=1).next()

#.bgm("song").clock(name="song", source="music.position").defaultClock(name="song")
: 全局 song 达到 12.5 后进入。 .at(value=12.5, clock="song")
```

#### 声明、名称与生命周期

- `clock()`／`clock(source="opaque")` 新建播放头局部匿名实例，并设为该头默认。每次创建有独立 ID；匿名只经当前 default 引用，不能跨头点名。更换为新匿名或具名默认时，旧匿名立即回收；同头挂在其 at 时无法继续执行切默认，其他头也不能改它的 default。停止该头取消等待并回收其匿名钟。
- `clock(name="song", source="opaque")` 声明会话全局具名钟，不自动修改当前头默认。全局名字只能有一个声明位置，不同位置重名为编译错误；同声明本会话首次执行创建／起计或绑定，后续执行只复用，不 reset、不换 ID。具名钟存续到会话结束，不随创建头停止，不提供脚本销毁／替换。
- `defaultClock(name="song")` 选择已创建具名钟，不创建、不 reset。每个新头 default 为空、不自动创建、不继承其他头。jump／call 不隐式换钟，return 不恢复历史引用。
- `resetClock()` 操作当前默认；`resetClock(name="song")` 操作指定具名钟。reset 保持 ID：内置归零，外部仅调用宿主可选 reset，不提供时保留来源值，不自动 offset。重置不改等待阈值、不回滚已执行内容。
- 名称大小写敏感。空 name 无效，不是匿名别名；没有隐式全局 default 名。Start 清除会话实例和等待，保留宿主来源配置。

#### 来源与数值

clock 绝不发起媒体播放。source 是宿主解释的不透明字符串，`source=""` 等价于省略；仅在省略／空 source 时，宿主可接管创建，否则采用由宿主 delta 驱动、从零开始的内置秒计时器。非空来源可为任意有限数值函数，单位由宿主定义，不要求真实时间、单调递增或音频；无法解析的外部来源保持无值，不回退内置钟。

Reader 明确支持 `source="music.position"`：它表示 Reader 当前 BGM 播放器以秒为单位的实际播放头位置，与脚本时钟的 name 无关。播放由 `.bgm(...)` 触发，clock 只引用数值；暂停时数值停留，跳转时跟随播放器，停止、加载未就绪或错误时无值并撤去该来源的旧样本。Reader 不模拟其他未定义来源，也不允许用点击替外部钟填入门槛值。VS Code 内置试读当前不播放音频，因此该来源保持无值；音频同步使用 Web／独立 WASM Reader 验证。播放／换曲须由 Main 的独立指令完成，再在后续锚点创建依赖新曲的辅助；同锚点或辅助内部换曲缺少媒体命令确认边界，同批 Core 可能仍使用上一曲已上报值。

来源暂时无值时保留该入口门控，其他可运行头继续。可知的参数、名称、重复声明和静态引用错误在编译／加载检查发现；文本解析与直接 AST 构造 Sequencer 使用相同加载校验；宿主可提供绑定预检材料，Core 不承诺枚举全部外部资源或预测未来值。getter／reset 失败留后台可定位诊断，getter 无值时不放行、不猜值、不静默回退内置，不把宿主异常直接抛给玩家；具体宿主接口在实现记录中核对。

内置暂停通过停止增加其 delta 表达；外部来源是否变化归宿主。选择不会隐式暂停钟。来源回退只改变后续门控，不撤销已经执行的内容，也不构成 seek／存档恢复。

#### 门控与源码顺序

clock／defaultClock／resetClock／at 只用于普通文本或指令锚点，不用于选择容器、选项、控制流或 AUTO 头，也不从 speaker 默认注入。每个普通文本／指令锚点至多一个 `.at(value=6, clock="song")`；value 必须有限，可为负。省略 clock 时，执行抵达入口根据该头当前 default 确定实例。缺默认、尚未创建的具名引用给可定位诊断，不暗建、不挂起等未来声明。可证明的先用后建前移检查；动态分支或宿主指定入口无法静态证明时，运行期仍保留脚本状态错误防御。这与已创建外部钟暂时无值继续等待不同。

at 在整个锚点进入前比较值，只有已知值 >= 阈值才执行本锚点标签和输出。它不替上一句生成 advance、不抢占 Main 的点击或其他 Core 等待。Main 提前确认可使执行先到门口等待，到阈值自动放行；未确认则到时也不跳过前句。辅助输出后直接继续至下一 at。

同锚点时钟／轨道控制和普通宿主标签按源码顺序处理，但 at 总在它们之前；不能靠同锚点尚未执行的 clock/defaultClock 为自己的 at 提供前提。内建控制由 Core 消费，普通标签交宿主，宿主回调不能重入执行。

例如当前值为 12，顺序到达 at 4／6／10／12，各节点均正常执行及派发副作用，最后每头只留下其末句；不是核心跳过过期节点。脚本循环与媒体循环未同步是作者责任，不要求媒体结束／轮次事件，执行预算仍适用。

#### 宿主驱动与观察

保留 `UpdateClocks(delta, sessionId)`、`PollClocks(sessionId)`、来源绑定／推送与只读快照的职责划分。每帧同一 delta 只提交一次；采用多轨呈现控制器驱动时钟时，不另行重复 UpdateClocks。来源更新带原 sessionId；旧会话输入后台忽略。

公开来源与观察 API：

| API | 约定 |
| --- | --- |

getter 异常或非有限返回值作为无值并记后台 Warning，不影响其他钟／头；reset 回调异常记诊断，不更换 ID、不回退内置，也不承诺媒体实际归零。读取输出和切语言不能隐含采样或解除门控。LaneId／OwnerLaneId 为现有公开字段命名，逻辑上表示播放头，不恢复旧 parallel/lane 模型。

### 2.9 辅助控制的完整具名形式

```ktory
#.track(source="Lyrics", name="lyric")
#.track(source="Ambient")
#.track(source="Init").await
#.awaitTrack(name="lyric")
#.stopTrack(name="lyric")
```

track／await／stopTrack／awaitTrack 只用于普通独立 # 指令，不作为文本、选择、AUTO 或 speaker 默认修饰符。source 指本文件已声明节；不从名字／扩展名猜测文件路径。外部文件必须显式 URL，但准确参数结构、URL 格式、resolver 和加载协议延期；尚不接受自创 scheme 或相对路径作为标准语法。外部文件入口未来从目标根节开始，调用命名节仍须显式 return。该延期不阻塞本文件 Main／辅助实现，也不删除跨文件能力。

同一普通 # 中多个 awaitTrack 按 Tag 源码顺序处理。某次等待挂起时，该锚点尚未执行的后续 Tag 暂停；目标停止后从原位置恢复，不重新判断该锚点的 at、不重跑此前副作用。所有控制与标签完成后，才交付普通指令拍并开始 Main 的 wait／next 计时；仅含内建控制的 # 可透明继续，不产生人工空停顿。此规则同样防止等待恢复时重复创建／停止或派发宿主标签。

## 3. 控制流拓扑与执行状态

### 3.1 循环控制（`.loop` 与 `-> break`）

#### 3.1.1 循环计数器规则
* **进入时计数**：`.loop(count=n)` 的计数以**进入所修饰节点的物理次数**为准（首次进入计为第 1 次）。`.loop(count=3)` 表示至多进入该节点 3 次。
* **缺省与边界**：`.loop` 与 `.loop()` 表示无限循环；所有整数 count <= 1（包括零和负数）均夹到一次，执行单次而不跳过节点；非整数或超过 int 范围报参数诊断。
* **作用域与生命周期**：计数器绑定于当前循环执行上下文。在内联分支执行、子过程调用及返回期间均保持。循环次数耗尽或显式退出时释放。从外部别处重新进入该源码节点时，计数器重置为 1。
* **重入副作用**：通过 `.loop` 重新进入节点时，**重新输出内容并再次执行挂载在该节点上的所有其他修饰符（包括副作用指令）**。`.loop` 自身复用计数器，不重复叠加循环层。

#### 3.1.2 跳出机制（`-> break`）
* **就近原则**：执行 `-> break` 时，退出当前执行栈中**最近的一层活动 loop**，释放该层计数器，并从该循环节点的后续指令继续执行。
* **宿主中断请求**：游戏宿主或表现层可向调度器主动发送 `Break` 信号，其语义完全等同于 `-> break`，支持在循环 choice 菜单展示期间强制中断并跳出。

### 3.2 容器生命周期与选择语义

#### 3.2.1 选项消费状态（`*` vs `+`）
* **会话级持久记录**：当玩家有效提交某个 `*` 子项时，核心将其唯一标识标记为“已消耗”。在当前剧情播放会话（Session）中，即使重新进入该容器，该项持续不可选。
* **生命周期范围**：消耗记录仅在当前会话存活。会话重启或新起游戏时重置。首阶段不实现跨游戏会话的磁盘持久化。
* `+` 子项永不消耗，可重复选择。

#### 3.2.2 零可选项越过
当 choice 容器由于 `*` 消耗耗尽、守卫条件不满足或 Handler 回退导致**无任何可选子项**时，核心自动越过该容器，平滑继续执行其后置指令。此行为属于合法拓扑流，零可选项本身不触发 Warning 或 Error；未知容器或未知游戏条件各自要求的 Warning 仍须报告。

### 3.3 跳转、调用栈与节终止语义

以下根节恢复行为针对 Main；辅助的结束边界见 §3.4。jump／call／return 均保持当前播放头身份。

```
           ┌───────────┐
           │ -> Label  │ ──► 清空调用栈，单向跳转至目标 (Jump)
           └───────────┘
           ┌───────────┐
           │ => Label  │ ──► 当前后置指令压栈，跳转至子过程 (Call)
           └───────────┘
           ┌───────────┐
           │ -> return │ ──► 弹栈，恢复调用前上下文 (Return)
           └───────────┘
           ┌───────────┐
           │  -> end   │ ──► 清空调用栈，跳至源码后方首个根节节点 (End)
           └───────────┘
```

1. **单向跳转（`-> Label`）**：彻底放弃当前返回路径，**清空活动调用栈**后进入目标。若跳转后无新调用却执行 `-> return`，核心抛出控制流错误。
2. **子过程调用（`=> Label` 与 `-> return`）**：`=>` 记录当前节点的恢复地址入栈；`-> return` 弹出栈顶并返回。
3. **节自然结束与 `-> end`**：
   - 在命名节内部走到末尾，或执行 `-> end`，其行为一致：**清空活动调用栈**，跳过后续所有其他命名节，从该节之后的**第一个根节节点**恢复执行。
   - 在根节内执行 `-> end`，直接终止整个脚本播放。

### 3.4 Main 与辅助播放头

```ktory
#.clock(name="song")
#.track(source="Lyrics", name="lyric")
: 请听这段旋律。
#.awaitTrack(name="lyric")
: 歌词执行已结束。
-> end

=== Lyrics ===
  : 第一行歌词。 .at(value=0, clock="song").duration(seconds=2)
  : 第二行歌词。 .at(value=3, clock="song")
```

#### 身份与权限

会话只有一个 Main，独占玩家输入；Main 可创建、点名停止和等待辅助。章节不带主辅属性，跳转／调用保留头身份。辅助有独立 PC、栈、循环和默认钟，只按 Core 控制流与 at 条件自动向前；不等打印／duration／wait／next／AUTO，不新增阅读模式或显示完成回调。

辅助遇到 track／await／stopTrack／awaitTrack 直接忽略；遇到选择整体跳过容器、所有分支及附带标签，不求值容器／选项条件，不消费选项。不能因共享章节含这些操作而静态禁止整节。无 at 的辅助文本可在同批依次输出，最终每头只留下末句，这是合法行为；可选编译警告不能要求每个辅助节点都必须有 at。

#### 实例、停止与等待

- track 默认只保证实例已创建并排入调度，不保证目标章节的初始化已经执行。依赖共享钟或其他初始化结果时，优先在 Main 创建共享资源，或用 `.track(...).await` 显式等待初始化章节结束；不能靠插入任意宿主标签或空拍碰巧让出调度。可静态确定的未等待初始化就引用其时钟，应在加载时诊断并提示显式等待；分支等无法证明的路径仍保留运行期检查。
- 目标节名不是实例名，允许多个辅助同时执行同一节。匿名 track 每次有效执行创建新 ID；没有可点名的外部 stop／awaitTrack 入口，但可自身 end、自然结束或会话清理。
- 具名辅助每会话只有一个声明位置，同名不同声明编译拒绝。同声明首次执行创建，后续忽略，包括已停止后；不能隐式替换或重启。终态记录保留至会话结束，执行头可销毁。
- `.track(source="Init", name="init").await` 创建或取得具名辅助并等待它结束；`.track(source="Init").await` 创建匿名辅助并等待本次实例。`.await` 无参数，必须紧邻同一普通 # 锚点上的 track；孤立、隔开其他标签、重复或传参数均为加载错误。重复具名 track 仍不重启，await 等现存活动实例，已结束则立即继续；匿名仍每次新建。等待期间暂停后续标签，恢复后不重跑前面的标签或 at。辅助忽略 track 与其 await。初始化依赖推荐此写法，默认 track 保持并发。
- stopTrack 仅 Main 生效。运行中目标停止并清理其执行等待；已声明但未创建／已停止为无操作，不预取消未来创建。不存在名字给可定位引用诊断。
- awaitTrack 仅 Main 生效。抵达时捕获实际已创建实例；运行中建立不可被 advance 绕过的 Core 门控，停止后自动继续；已停止立即继续。尚未创建不建立等待，给可定位诊断，不能等未来创建而把唯一创建者 Main 挡住。等待边仅 Main→Aux，不引入互等检测。
- 停止只停止执行，不强制清屏、不发起媒体停止。停止和自然 EOF 都解除 await，终止原因可区分。

#### 完成与调度

Main 命名节 EOF／end 按 §3.3 清栈进入源码后根节点；辅助命名节 EOF／end 结束自身，不寻找根节后续。所有头的 call 都要求显式 return，EOF 不是隐式返回。

Main 执行结束立即结束会话并停止辅助，不默认 join 所有轨。需要等辅助则由 Main 显式 await。辅助 EOF 即执行完成，与最后显示寿命无关：10 秒末句已执行至 EOF、duration 2，10 秒解除 await，Main 若因此结束当时通知，宿主可显示到 12 秒。Ktory 不自行开启新故事。

同轮就绪输出／副作用／终止通知顺序确定，末句先于停止或会话结束通知。保留单次／批次指令预算、活动头上限及公平调度，零时长循环不得无限占用；合法语法不免除预算保护，已执行副作用不回滚。

#### 旧语法迁移

旧 `#parallel/#lane` 不再是可执行语法，给明确迁移诊断，不作为普通宿主指令降级。作者将旧 lane 正文提取为中立章节，用 Main 的 track 启动，按原故事需要显式 await。不能静默改写成无 join 的 track；也不保证机械等价转换：旧嵌套创建、循环重复创建并 join 可能需要依照 Main-only 权限、具名每会话一次规则重新组织。

外部事件信号、race、join-all、暂停协议、自动回滚和中途持久化不因本次迁移进入范围。

## 4. 数据结构与输出协议

### 4.1 已确认的数据要求

- **文件默认语言**：`DefaultLang` 字符串（显式声明时为对应语言代码；缺省且存在 `@locale` 时为 `"zh"`；无任何 `@locale` 时为 `null`，表示未本地化）。
- **说话人映射模型（SpeakerDefinition）**：
  - 维护唯一识别键、别名集合（`HashSet<string>`，严格区分大小写）、本地化显示名称字典（`Dictionary<string, string>`）。
  - `KtoryFile` 提供别名到说话人实体的 O(1) 映射表及安全反查与回退解析。
- **选项文本本地化（ContainerItem）**：
  - 维护 `LabelVariants` 字典（`Dictionary<string, string>`），支持根据当前语言与默认语言获取本地化标签。
- **对白与输出载荷（TextPayload）**：
  - 包含当前语言下的 `Content`、正文实际语言 `ActualLanguage`（未本地化脚本输出 `null`）、请求语言 `RequestedLanguage`、动态解析出的本地化 `Speaker` 及其独立的实际语言 `SpeakerActualLanguage`（未声明说话人或未本地化时为 `null`）；名字与正文可能使用不同语言，未声明说话人的实际语言为空。
- **叙事记录**：会话内记录已消耗选项 ID；第一阶段不要求将其磁盘持久化。

包含纯文本的正文或选项版本额外保留有序 `TextSegment`（`Content`、`IsLiteral`）：`TextStep.TextVariantSegments`／`ContainerItem.LabelVariantSegments` 按语言键保存，普通版本无需片段列表。运行时 `ResolvedLocalizedValue.Segments` 与其选中的语言版本一起输出，包括默认／第三语言回退与副语言；没有纯文本片段时为 null。

`Content` 仍为各片段内容顺序拼接的兼容投影，不含围栏。它不能单独区分字面的 `<b>` 与真实富文本。渲染器在 `Segments` 存在时必须按片段处理：`IsLiteral=true` 用目标渲染器的纯文本节点／转义方式显示并保留换行和空白，其他片段使用原有富文本处理。不得将整个 `Content` 再作为富文本解析，或把整拍的所有语言统一标成纯文本。HTTP／WASM 采用相同的 `segments/content/isLiteral` JSON 形状；主／副结果各自携带片段。

独立控制流表示的扩展与外部演出事件回调仍须按具体问题讨论；当前呈现输入的会话标识与拒绝规则已由 §5.2.2 明确，不再列为开放语义。
不在行为规则确定之前写出具有误导性的完整接口。工程文档中的候选字段不自动成为本节规范。
新增共享配置、表情清除输出及本次演出通知的标识、匹配和生命周期需求见 §1.4；不得先以字段名称代替行为决策。

### 4.3 输出交付、显示身份与双本地化

- 每次输出可识别会话、源播放头稳定 ID、Main／辅助身份、可选实例名、本次内容身份和源码位置。匿名头也可追踪；公开输出为 `StoryOutput`：`Kind/Sequence/SessionId/TrackId/TrackName/IsMain/Token/Payload/Choice`；不增加新的多元 token 协议。
- 执行头和显示位置分离。标签／宿主配置决定路由，实例名可以作为配置依据，但不自动映成 UI，不要求一轨固定一个框，也不增加 channel／track 显示参数。每个播放头只有一条当前语句，同头后句进入即撤下前句，即使路由到不同显示位置。不同头共用位置时由宿主确定路由与覆盖策略，不能用显示位置改变同头的语句寿命。
- 输出是顺序交付的事实，不能只读取操作结束时的活动头快照：辅助可在同批产生多条输出并结束，所有应执行的标签和末句仍须交付。内容输出先于对应停止／会话结束通知。
- `GetActivePresentations()` 等观察用于快照，不替代交付事件。`CurrentPayload/CurrentChoice/CurrentPresentationToken` 是 Main 兼容入口，不能代表全部辅助输出。`Sequencer.OnOutput` 按顺序发出 `StoryOutput`；Kind 为 `Content/LanguageRefresh/TrackEnded/SessionEnded`。`LastOutputs` 保存最近一次执行或语言刷新批次，下一次执行／刷新替换；只读观察不消费，不是无限历史。
- `GetRetainedPresentations()` 只保留每个头当前仍显示的语句，包括未被后句替换的已结束辅助末句，以及 Main 当前选择。空 `:`、后续指令输出或选择进入时结束前句显示；等待下一句的 at 门控不等于下一句已进入。Core 不保留同头多个历史语句用于当前呈现，宿主的阅读历史可另行保存。
- 宿主将当前内容提前隐藏后调用 `ReleaseOutput(token)`，须在执行／输出回调返回后处理；释放只影响指定内容，新会话使旧保留对象失效。`LanguageRefresh` 按 token 更新当前显示，不重跑路由标签，不重新显示已退出／隐藏的内容，也不重启 duration。`LanePresentation.IsMain` 显式标角色，输入活动性仍只属于 Main 当前门控。
- `PresentationToken(sessionId, presentationId)` 仍区分输入来源，presentationId 会话内唯一。Main 当前门控校验推进权限；旧内容保留显示不恢复旧 token 推进权。旧 duration／淡出回调只处理其内容，不清除替换它的新内容。
- 保留 §2.5.4 的 Primary／Secondary、实际语言和纯文本片段。语言刷新不推进、不重放副作用、不重新采样时钟或重置计时；已结束辅助但仍显示的内容保留足够文本来源用于无副作用刷新，不必保留执行头。
- stop／会话结束清理执行等待及旧输入授权；显示是否继续、何时隐藏或接上新故事由宿主决定，不将核心执行销毁等同于强制清屏。

## 5. 运行时与接入

### 5.1 术语边界

| 术语 | 含义 |
| --- | --- |
| 原始点击 | 来自玩家的输入；不等同于播放器必然收到 `next` |
| 快速显示全文 | 表现层完成当前句文字呈现的操作，不是核心推进操作 |
| 文本就绪 | 接入层判定的呈现状态，不是 Ktory 核心状态 |
| `next` | 接入层决定后发送的定向推进请求，核心不检查文字呈现进度；须定位 Main 的具体 presentation（§5.2.4），不隐含全会话下一拍 |
| 演出推进条件 | 当前由游戏侧判断并控制 next 发送；新增目标允许脚本声明依赖，真实事件仍由游戏判定，具体匹配与推进协议见 §1.4 待设计项 |

### 5.2 文本呈现与推进契约

以下呈现推进契约用于 Main；辅助直接 Core 推进，不依赖文本就绪。身份与输入所有权见 §5.2.4。

1. Ktory 向接入层提供当前内容及相关声明；呈现采用何种效果不属于核心协议。
2. 接入层处理原始点击，并依据自身呈现状态决定快显、忽略或发送 `next`。
3. 快显完全由表现层执行，不要求 Ktory 更新执行位置或获知快显完成。
4. 接入层判断文本是否满足推进条件；核心不维护文本 `canAdvance`，不要求接入层回报文本就绪后才允许推进。
5. 收到 `next` 时，核心按剧情控制流处理；不读取文字播放百分比、不等待文字动画。当前需要选择时，普通 `next` 不推进，必须提交选项才能解除选择造成的推进限制，见 §5.2.1。

接入层内部可以使用异步技术，但呈现任务的完成不成为核心推进的前置回调。

声明文本播放策略不等于核心执行该策略。标准快显点击只完成全文显示，不同时推进，见 §2.6；自定义宿主输入策略仍须保持令牌隔离与单一推进责任。

### 5.2.1 选择提交

- 普通推进与选择提交是不同操作。选择菜单出现后，核心处于需要选择的结构状态；普通 `next` 不能绕过该状态。
- 接入层向播放器提交选项，由播放器决定对应分支。选项呈现和输入方式仍属于表现层。
- 只有收到有效选项才能解除这一选择状态。过期／重复输入按 §5.2.2 忽略；令牌仍指向当前菜单但选项不存在或不可选时，属于真正的非法选择并报告错误，不能伪装成过期输入吞掉。
- 该限制来自未确定的剧情分支，与文字是否显示完的表现门控不同。解除当前选择状态不保证后续节点一定可普通推进，例如后续仍可能是另一个选择。

**选择提交包含一次继续执行。** 不要求宿主先提交选择再额外调用 `next`。有效提交后，播放器沿所选分支执行到下一处内容输出、选择或结束位置；不自动越过新输出的第一句。分支中的普通 # 指令按 §2.2.2 默认自动，不为每条动作额外消费点击；到达文本／输入拍仍保留该拍的有效输入边界。

接入层不能再为同一次选择附加一个普通 `next`，否则可能越过新内容。若需先播放选项确认动画，接入层先记录选择意图，动画结束后再提交；播放器不等待该动画，也不需要暴露“已提交但尚未执行”的中间状态。

### 5.2.2 输入生命周期与相邻契约（2026-09-27）

下列令牌协议适用于单轨及多轨。会话内 presentationId 全局唯一，通过活动上下文查找路由输入（§4.3、§5.2.4）；无需增加 laneId。失效、原令牌捕获与重复投递忽略的原则保持不变。

- `.next(seconds=waitTime)` 的显示后计时、缺省为零、无文本节点的计时起点，以及 `.wait/.next` 并行组合规则已确认，见 §2.6。
- 推进、选项提交、Break 及表现计时／完成回调须对应其来源会话和呈现。切语言是会话设置，只要求来源会话仍有效，允许同会话的旧拍或已完成状态。过期输入及已被消费操作的重复投递正常忽略，只记后台 `InputIgnored` 诊断，不进入 `Error`、不中断剧情，也不重放标签或消费选项。
- 每次 `Start` 产生新的会话标识；旧会话闭包即使携带相同拍号也不能作用于新会话。关闭或替换播放器前先使旧会话失效，并清理宿主订阅与排队工作。只携带拍号的旧接口仅用于同步兼容，不承诺跨会话隔离。
- 异步回调必须在创建时捕获完整会话／呈现令牌，投递时使用原令牌；不能在旧回调执行时重新读取当前令牌来绕过隔离。一次选择已执行到下一输出，不附加一次推进。
- 该协议隔离旧输入，不提供世界状态事务、持久化恢复或外部演出信号语法。`Warning` 表示可恢复的脚本／能力问题，`InputIgnored` 表示后台输入生命周期诊断，二者不混同。
- `#AUTO` 的源码作用域及外部子过程不继承规则已由 §2.7 确认；自动请求的具体投递顺序及未覆盖的嵌套组合边界仍需与基础执行契约一并明确，不能借本项重新解释已确认条款。

Core 使用 `PresentationToken(string sessionId, long presentationId)`，由 `CurrentSessionId` 与 `CurrentPresentationToken` 提供当前身份。令牌接口为 `Step(token)`、`SubmitChoice(optionId, token)`、`Break(token)` 和 `SetLanguage(locale, token)`；最后一项只校验有效会话，不以旧拍号拒绝同会话语言设置。`InvalidateSession()` 使当前会话执行与输入授权失效并置为 `Completed`，不派发新剧情标签；宿主决定旧显示收尾。失败的 Start 则使身份失效并保留 `Error` 诊断状态。之后成功 `Start()` 才建立可继续执行的新会话。

`PresentationController.CurrentPresentationToken` 保存最近一次 `SetupForCurrentBeat()` 对应的身份；它的 `Update(deltaTime, token)`、`NotifyPrintingFinished(token)`、`HandleUserClick(token)`、`RequestAdvance(token)` 均校验这份身份。默认 `AutoStepSequencer == true` 时控制器唯一负责推进，事件订阅者不能再 Step。宿主管理推进时设置为 `false`，通过 `OnAdvanceRequestedWithToken` 捕获请求令牌，在接受该请求后推进并建立下一拍；已忽略的回调不得重新 Setup 当前拍或重置计时。旧的无令牌调用和 `OnAdvanceRequested` 保留同步兼容，不用于异步排队。

### 5.2.3 条件求值策略（2026-09-27）

真实游戏的 Sequencer 使用内置 `DefaultExpressionEvaluator` 遇到未知条件时发出带位置与条件内容的 `Warning`，并按 `false` 处理，不因缺少宿主能力而放行剧情。已知条件仍按实际结果求值；游戏状态与复杂表达式由宿主通过 `IExpressionEvaluator` 提供。

独立试读须显式启用宽容策略（`IgnoreUnknownConditions = true`），使无法求值的外部选项条件可供试读；此设置不代表条件在真实游戏中成立。内置求值器的模式选择不能代替宿主真实世界状态。

### 5.2.4 Main 输入与辅助执行

只有 Main 接收玩家 Step、choice 和快显输入，来源令牌必须仍对应 Main 当前可推进位置。辅助输出存在不构成输入所有权；不能用旧辅助显示令牌推进 Main。旧／重复／迟到请求只记后台 InputIgnored，不能串句或广播。

Main 的 PresentationController／多轨接入包装处理 trial、打印完成、wait／next／AUTO。辅助执行由 Core 自动安排，不建立辅助 wait／next 定时器，不等待 NotifyPrintingFinished；duration 等显示状态仍可由 renderer 独立保存。自动策略共用有效推进许可，但不能每帧机械点击导致快显；自动条件到期后若 wait 未结束，保留自动到期状态，限制解除后重新判定。

同一时刻每个有效 Main advance 只有一个提交者。控制器自动 Step 与宿主事件回调不能重复提交。时钟 delta 同样每帧只交付一次，选择／语言刷新不隐含更新。

重启／关闭使旧会话与输入失效；显示保留与删除由宿主处理。执行完成不等 duration，不代表已交付的呈现必须立即销毁。

### 5.3 Unity 接入

**多轨接入要求**：Unity 宿主须消费按顺序交付且来源明确的内容及终止通知，输入只路由 Main，显示位置由标签／配置决定；不能只读取 `CurrentPayload` 或最终活动头快照。新接口实现与验证状态见实施记录。主／副语言由语义载荷分别提供，renderer 决定布局。调试视图须区分 Main／辅助与来源实例；本机 Core／桥接通过不代替另一设备的 Unity 导入、呈现、媒体同步和生命周期验收。

第一阶段实现基础对话框、立绘与输入接入。其执行和文本选择应遵循本规格。当前演出门控在游戏侧实施；新增目标将脚本剧情依赖与真实资源／事件绑定分开，通过可复用编辑器配置及运行接入落实。该工具及通知协议待设计，首阶段无需开发完整配置工具。

已有实际 Unity 接入在另一设备。本规范保留上述最终验收要求，不要求当前设备重建游戏工程。能够脱离 UI 复现的反馈须转为 Core／桥接回归；渲染、资源、事件接线与平台行为由 Unity 环境补充验证。

#### 5.3.1 运行中调试（2026-09-26）

真实项目验证需要的通用窗口位于 Package `Editor/Debugging`，菜单为 `Window/Ktory/Debugging`。通过 Editor 条件编译的 `IKtoryDebugTarget` 注册真实宿主会话，支持多个实例；本版不创建第二播放器、不连接独立构建的远程 Player、不提供强制跳过。

- Core 仅提供当前源码位置、值快照和可选 `OnTrace` 诊断事件，不引入 Unity 或真实时钟。事件覆盖节点进入、标签派发尝试、有效选项提交、调用、返回、跳转／break、结束、`Warning`、后台 `InputIgnored` 及执行错误；观察器异常不改变执行，窗口读取不产生事件。标签尝试不代表外部演出成功。
- `PresentationController` 暴露真实快显锁、最低停留和自动延迟的剩余值及策略来源。文字显示阶段的停留／自动值是尚未开始的时长；窗口不能调用 Update 或建立新呈现。无活动拍时不得显示上一拍的 AUTO 为当前生效策略。
- `ChoicePayload.LineNumber` 与 `ChoiceOption.LineNumber/RequestedLanguage/ActualLanguage` 透传选择及选项源码和真实语言；正文、说话人及选项各自报告实际语言。双缺译的第三语言回退规则见 §2.5。
- 切语言、正常点击、合法选择和重启经过宿主真实处理路径；换语言不推进、不重放标签、不重置固定计时。项目自有打字机、演出资源、额外输入门禁与 AUTO 由项目提供信息，不由 Package 推测自定义修饰符含义。
- 注册期间收集历史，窗口开关不影响会话。全部实例合计最多 2000 条；退出 Play Mode／重编译撤销订阅，销毁或替换会话清理注册。UI、注册表与历史不进入正式构建。

此决策对应 C03–C06、C08；具体适配、扩展边界和 Unity 验收步骤见 [Debugging 接入说明](ktory-unity-debugging.md)。Core 测试与 Unity 实机证据分别记录。

### 5.4 独立试读

当前接入形态包括本地 HTTP Reader、WASM Reader 及 VS Code 内的 WASM 试读。VS Code 扩展读取明确打开的编辑器文档，支持手动重载未保存内容；重载开始新会话。它复用核心与 Reader 的现有行为，不另设语言语义。安装与使用见 [VS Code 扩展说明](../src/Ktory.VSCode/README.md)，构建与验证见[仓库工作流](ktory-workflow.md#vs-code-扩展开发与验证)。

1. 不依赖 Unity，至少提供语言选择。
2. 执行基础行为，跳过不能解释为基础行为的内容，不要求外部状态模拟。
3. 显式启用宽容求值器，对无法求值的外部选项条件忽略条件并展示全部选项，供作者选择；不自动执行所有分支，不依赖游戏内置求值器的默认策略。
4. 试读的宽松行为不改变真实游戏中的条件语义，也不证明外部演出正确。
5. §1.4 的显式信号依赖需要独立试读策略；当前跳过未知演出不意味着信号已发生。未来越过或人工确认交接点须明确标示，具体交互待设计。

Reader 支持的时钟路径只有两种：未指定 source 时使用 Ktory 内置钟；`source="music.position"` 时读取 Reader BGM 播放头。其他外部 source 无法解析时保持无值，不构成另一种模拟模式。

**多轨与双语**：HTTP／WASM 桥接及共用 Reader 使用同一 Core 的 Main／辅助执行模型、顺序输出、Main 输入和显式 await，消费结构化主／副语言输出。副语言开关只重绘，保留打印和计时。Reader 对 `music.position` 读取当前 BGM 播放器的实际秒位置；无法解析的外部来源保持无值和门控，不提供模拟放行。完整时间轴编辑器仍是独立工具需求。

解析错误（包括悬空修饰符）须停止加载并显示可定位诊断；重载失败不得继续旧剧情。未知插值与未覆盖的行内条件展示规则仍须单独核验，不据此增加模拟系统。

## 6. 综合场景用例与开发验收断言

### 6.1 用例一：多语言回退与标签确认

```ktory
主角:
  @zh: 这里真冷。
  .emotion(shiver)
```

* **测试前提**：文件 `defaultLang = "zh"`。播放器请求语言设置为 `"en"`。
* **断言结果**：
  1. 输出 `TextPayload.Content == "这里真冷。"`。
  2. 输出 `TextPayload.ActualLanguage == "zh"`。
  3. 输出 `TextPayload.RequestedLanguage == "en"`。
  4. 绝不输出任何伪造的缺译占位符。

### 6.2 用例二：选项提交流程与首句停顿

```ktory
#choice
  * [调查房门]
    主角: 门已经被人从外面反锁了。
    主角: 看来只能另找出口。
  + [放弃]

主角: 接下来怎么办？
```

* **测试前提**：核心推进至 `#choice`。状态变更为 `ExecutionStatus.AwaitingChoice`。
* **执行动作**：宿主调用 `SubmitChoice("调查房门")`。
* **断言结果**：
  1. 核心状态变更为 `SuspendedAtBeat`。
  2. 核心派发第 1 句台词载荷：“门已经被人从外面反锁了。”
  3. 核心指针停留在第 1 句，**绝不自动穿过**至第 2 句。
  4. “调查房门”项在会话消耗集合中被记录，再次进入该 choice 时该项置灰或标记为已读。

### 6.3 用例三：文字快显与自动步进倒计时时序

```ktory
主角: 这是一句需要测试呈现倒计时的重要线索。
  .skippable(enabled=true)
  .next(seconds=2)
```

* **时序与断言验证**：
  1. **T=0s**：表现层启动打字机，文字逐字输出。核心处于 `SuspendedAtBeat`。
  2. **T=0.5s（未打完）**：玩家点击屏幕。表现层捕获该输入，瞬时将整句文本全部排印在屏幕上（快显生效）。表现层**严禁**在此时向核心发送 `Step()`。
  3. **T=0.5s 时刻**：由于显示已完成，表现层启动 2.0 秒倒计时（计划于 T=2.5s 触发）。
  4. **T=1.2s**：玩家再次点击屏幕。表现层判定文字已显示且处于等待阶段，**立即取消未触发的 2 秒计时器**，向核心发送 `Step()`，核心推入下一拍。新的一拍绝不会在 T=2.5s 时被残余计时器误触发推进。

### 6.4 用例四：Hub 循环调查与 Break 机制

```ktory
=== Room_Investigation ===

  #choice.loop
    * [查看书桌]
      #do .sfx("paper")
      主角: 桌上有一张泛黄的日记碎片。
    * [检查窗户]
      主角: 窗户被铁栅栏焊死了。
    + [尝试撞门]
      主角: 门纹丝不动，撞得肩膀生疼。
    + [放弃思考] -> break

  主角: 我们离开这里吧。
```

* **测试前提**：宿主显式指定 `Room_Investigation` 为入口。
* **断言结果**：
  1. 选择 `[查看书桌]` 并提交：核心进入内联分支，先派发 `#do` 动作并默认继续，随后停在台词“桌上有一张...”。台词执行完毕后，控制流根据 `.loop` 重新激活当前 `#choice`。
  2. 再次激活菜单时，`[查看书桌]` 标记为已消耗，其余三项仍可点击。
  3. 选择 `[放弃思考]` 或宿主外部发送 `Break()`：核心跳出循环，直接执行主干后续台词“我们离开这里吧。”
