### 1.1 文档定位与关系

### 1.2 第一阶段交付范围

1. **核心解析器与剧情调度器（Core Parser & Sequencer）**：对白、分支选择、循环调查、调用栈、会话内叙事记录（访问历史）。
2. **多语言同文件维护**：同一 `.ktr` 脚本内多语言变体解析与请求缺译时的回退输出。
3. **独立试读工具（Standalone Runner）**：不依赖 Unity 环境，支持语言切换与未知外部条件忽略。
4. **Unity 基础接入组件**：基础对话框与立绘驱动，满足阶段性验收。

> **阶段非目标（Explicit Out of Scope）**：
> 第一阶段不包含持久化存读档、配音系统、翻译文本自动提取/回填工具、Timeline 深度绑定或核心内部异步演出等待。

### 1.3 核心架构边界与原则

1. **单向离散步进（Step-Driven）**：核心调度器基于离散“拍”（Beat/Step）推进。核心不发起异步等待视听演出的行为。
2. **渲染与门禁彻底下放**：
   - 文本呈现进度（打字机、渐显、即时显示）、快显控制（Fast-forward）、文本就绪判定（`canAdvance`）**完全由接入层持有**。
   - 核心不维护文本门禁锁，不记录打字机完成百分比，亦不等待文本就绪回调。
3. **外部状态解耦**：核心仅维护会话内脚本消耗历史与调用栈；外部背包、角色属性等由宿主系统驱动，不侵入核心内部状态。

## 2. 词法与语法规范（Syntax Specification）

### 2.1 基础概念：锚点与修饰符（Anchor-Decorator Model）

脚本由离散的执行节点构成，词法上分为两类：
* **锚点（Anchor）**：显式声明一个执行节点。包括文本对白行、旁白行、指令拍行（`#`）以及容器子项行（`*` / `+`）。
* **修饰符（Decorator）**：以 `.` 开头，严格吸附至离它最近的上方锚点，作为该节点的元数据。修饰符可链式书写或缩进换行书写。

#### 修饰符参数规则
* **无参等价性**：`.tag` 与 `.tag()` 在解析层完全等价，均传递无参修饰符。
* **零值独立性**：显式写入 `.tag(0)` 解析为包含单一整数实参 `0`，不得合并为无参形式。具体语义由修饰符自身约定解释。

### 2.2 节点类型与书写规则

#### 2.2.1 文本与对白锚点（Text / Dialogue Anchor）
```ktory
说话人: 文本内容
: 匿名旁白内容
```
* **首冒号规则**：词法解析仅以行内首个半角 `:` 或全角 `：` 分割说话人与正文。其后出现的冒号均视为文本内容。
* **匿名旁白**：冒号前为空白或无说话人时，收敛为匿名文本节点（`Speaker = null`）。
* **行内富文本**：支持行内转译（`*斜体*`, `**粗体**`, `~~删除线~~`, `[基准]{注音}`）及原生引擎标签直通（如 `<color=red>`）。禁止使用块级 Markdown（如标题 `#`、列表 `-`、多行代码块）。

#### 2.2.2 指令拍与空拍（Directive Anchor）
以 `#` 开头的行。若其下方无归属的子项，该行作为**独立无文本指令拍**：
```ktory
// 独立指令拍：占据一次步进，触发挂载修饰符后挂起，不因无文本而自动穿过
#do .camera_shake(0.5)

// 纯停顿拍（空拍）：等待玩家输入或表现层信号
#
```

#### 2.2.3 容器与子项判定（Container & Items）
解析器**严格根据缩进及其下方是否存在归属子项**判定 `#` 行是容器还是独立指令拍：
* **容器判定**：若 `#` 锚点下方存在缩进的 `*` 或 `+` 子项，则解析为容器节点。
* **名称解耦**：`#` 后的标识符（如 `#choice`）仅作为 Handler 查找名称。`#choice` 不是解析器保留关键字。配套 SDK 默认将 `ChoiceHandler` 绑定至名称 `choice`。
* **子项标记**：
  * `* [选项文本]`：一次性子项（有效提交后在当前会话内置为已消耗）。
  * `+ [选项文本]`：持久可重复子项。
* **Handler 缺失回退机制**：
  * 遇到未注册对应 Handler 的容器，解析器与运行时不得崩溃或挂死。
  * 运行时发出包含原容器名称与源码位置的 `Warning`（严禁静默吞掉）。
  * 降级回退至基础 `choice` 行为展示子项并等待输入。若子项全部不可选或无子项，自然越过该容器。

### 2.3 缩进排版与语法诊断标准

缩进在 Ktory 中具备结构界定语义：
1. **容器子项**：必须相对容器声明行进行缩进。
2. **内联分支正文**：必须相对其所属的子项行进行更深层缩进。
3. **退出界定**：行首缩进退回至父级层级时，显式终结当前子块或容器。
4. **诊断原则**：
   - **Warning（可恢复）**：排版层级的微小偏差但能通过上下文无歧义推断归属时，报出 Warning，交由代码格式化器规范化。
   - **Error（结构歧义）**：缩进导致结构归属不明或产生分支歧义时，必须立即报告语法错误，严禁解析器隐式猜测。

### 2.4 节（Section）与根节（Root Section）

```ktory
// 根节正文（Root Section）
主角: 故事从这里开始。

=== Sub_Plot ===
  // 命名节正文：必须比声明行缩进
  艾莉丝: 这是支线内容。
  -> return

// 缩进退回顶格，恢复根节
主角: 支线之后的主干故事。
```

* **命名节**：`=== Label ===` 声明命名节。其内部正文必须相对声明行缩进；缩进退回该声明层级即宣告该节结束。
* **根节执行流**：未包含在任何命名节的代码构成根节。根节按源码线性顺序执行，**遇到命名节声明行时自动跳过其整个正文**，继续执行其后的根节节点。
* **进入方式**：命名节仅能通过显式跳转（`-> Label`）、调用（`=> Label`）或宿主 SDK 指定入口启动。

### 2.5 多语言声明与回退规则

| 特性 | 规范定义 |
| :--- | :--- |
| **文件组织** | 同一脚本文件内通过 `@locale:` 维护多语言变体；允许单语言直接书写。 |
| **默认语言** | 脚本由文件级元属性指定 `defaultLang`。 |
| **缺译回退** | 当请求语言（Requested Locale）缺失时，自动回退至 `defaultLang` 对应文本。 |
| **语言标签透传** | 调度器输出给表现层的载荷中，必须明确携带 `ActualLanguage`，严禁将回退文本标记为请求语言。 |

```ktory
艾莉丝:
  @zh: 你好，旅行者。
  @en: Hello, traveler.
  .emotion(smile)
```

### 2.6 表现层修饰符标准约定

`.next`、`.skippable`、`.wait` 在核心中均按通用 Decorator 解析，不属于核心保留关键字，核心不负责其调度执行。但为保证配套试读器与 Unity 接入行为一致，接入层须严格遵循以下约定：

```
[文本节点呈现流程]
  开始显示 ──► [文字打印/渐显阶段] ──► 打印完成 ──► [句后停留阶段 (Hold Time)] ──► 触发推进 (Advance)
                      ▲                                      ▲
           .skippable 约束此阶段                  .next(t) / .wait(t) 约束此阶段
```

| 修饰符语法 | 作用阶段 | 表现层标准实现语义 |
| :--- | :--- | :--- |
| `.skippable(false, [t])` | 文字显示中 | **仅限制文字快显**。在当前句出现的前 `t` 秒内禁止点击快显全文（缺省 `t` 时整句显示期间均禁止）。**不限制**文字完全显示后的普通推进或自动推进。 |
| `.next(t)` | 显示完成后 | **自动步进约定**。文字完全显示后，停留 `t` 秒自动向核心发送 `next` 推进信号。在 `t` 秒内若玩家点击，**立即提前推进**并取消未触发的计时器。 |
| `.wait(t)` | 显示完成后 | **强制最低停留约定**。文字完全显示后，强制停留 `t` 秒。玩家在 `t` 秒内点击时，**保留确认输入（排队）**，待 `t` 秒满后立即自动发送 `next`，无需玩家二次点击。 |
| `.wait` / `.wait()` | 显示完成后 | **预估阅读时间**。时长由该句实际输出语言的文字量与文件预估参数计算，从文字显示完毕后开始计时。 |

* **快显与自动计时**：若文字显示中途被允许快显点击，快显完成瞬间视为“文字显示完成”，`.next(t)` 的 `t` 秒倒计时自该瞬间起算。该次快显点击不得直接导致跳入下一句。

### 2.7 区域自动播放（`#AUTO` / `#AUTO_END`）

用于定义由脚本完全掌控节拍、无需玩家交互的自动化演出区间。

1. **宏标记行为**：
   - `#AUTO`：进入区域即刻启用自动步进策略，本身不产生可观察的点击停顿。
   - `#AUTO_END`：离开区域时穿过该行，随后关闭自动模式，不产生多余空拍。
2. **步进规则**：
   - 区域内节点若未声明停留，默认在呈现可放行时立即推入下一步。
   - 声明 `#AUTO.wait` 时，区域内有文本的拍默认应用该语言的预估阅读时间。
   - 局部修饰符优先级高于区域默认值：局部 `.wait(3)` 覆盖为 3 秒；局部 `.wait(0)` 覆盖为 0 秒（立即推进）。
3. **源码作用域（Lexical Scope）**：
   - AUTO 模式严格依源码位置生效，**不随调用栈向外部继承**。
   - 从 `#AUTO` 块调用外部命名节（如 `=> Sub_External`），子过程中不继承 AUTO；子过程返回原区域后，继续遵循原区域 AUTO 规则。

## 3. 控制流拓扑与执行状态

### 3.1 循环控制（`.loop` 与 `-> break`）

#### 3.1.1 循环计数器规则
* **进入时计数**：`.loop(n)` 的计数以**进入所修饰节点的物理次数**为准（首次进入计为第 1 次）。`.loop(3)` 表示至多进入该节点 3 次。
* **缺省与边界**：`.loop` 与 `.loop()` 表示无限循环；`.loop(0)` 与 `.loop(1)` 等价，均表示执行单次、不重复进入（零值不跳过节点）。
* **作用域与生命周期**：计数器绑定于当前循环执行上下文。在内联分支执行、子过程调用及返回期间均保持。循环次数耗尽或显式退出时释放。从外部别处重新进入该源码节点时，计数器重置为 1。
* **重入副作用**：通过 `.loop` 重新进入节点时，**重新输出内容并再次执行挂载在该节点上的所有其他修饰符（包括副作用指令）**。`.loop` 自身复用计数器，不重复叠加循环层。

#### 3.1.2 跳出机制（`-> break`）
* **就近原则**：执行 `-> break` 时，退出当前执行栈中**最近的一层活动 loop**，释放该层计数器，并从该循环节点的后续指令继续执行。
* **宿主中断请求**：游戏宿主或表现层可向调度器主动发送 `Break` 信号，其语义完全等同于 `-> break`，支持在循环 choice 菜单展示期间强制中断并跳出。

### 3.2 容器生命周期与选择语义

#### 3.2.1 选项消费状态（`*` vs `+`）
* **会话级持久记录**：当玩家有效提交某个 `*` 子项时，核心将其唯一标识标记为“已消耗”。在当前剧情播放会话（Session）中，即使重新进入该容器，该项持续不可选。
* **生命周期范围**：消耗记录仅在当前会话存活。会话重启或新起游戏时重置。首阶段不实现跨游戏会话的磁盘持久化。
* `+` 子项永不消耗，可重复选择。

#### 3.2.2 零可选项越过
当 choice 容器由于 `*` 消耗耗尽、守卫条件不满足或 Handler 回退导致**无任何可选子项**时，核心自动越过该容器，平滑继续执行其后置指令。此行为属于合法拓扑流，不触发 Warning 或 Error。

### 3.3 跳转、调用栈与节终止语义

```
           ┌───────────┐
           │ -> Label  │ ──► 清空调用栈，单向跳转至目标 (Jump)
           └───────────┘
           ┌───────────┐
           │ => Label  │ ──► 当前后置指令压栈，跳转至子过程 (Call)
           └───────────┘
           ┌───────────┐
           │ -> return │ ──► 弹栈，恢复调用前上下文 (Return)
           └───────────┘
           ┌───────────┐
           │  -> end   │ ──► 清空调用栈，跳至源码后方首个根节节点 (End)
           └───────────┘
```

1. **单向跳转（`-> Label`）**：彻底放弃当前返回路径，**清空活动调用栈**后进入目标。若跳转后无新调用却执行 `-> return`，核心抛出控制流错误。
2. **子过程调用（`=> Label` 与 `-> return`）**：`=>` 记录当前节点的恢复地址入栈；`-> return` 弹出栈顶并返回。
3. **节自然结束与 `-> end`**：
   - 在命名节内部走到末尾，或执行 `-> end`，其行为一致：**清空活动调用栈**，跳过后续所有其他命名节，从该节之后的**第一个根节节点**恢复执行。
   - 在根节内执行 `-> end`，直接终止整个脚本播放。

## 4. 数据结构与输出协议

### 4.1 已确认的数据要求

- 文件具有默认语言信息，具体表示待定。
- 文本具有语言变体；表现输出包含所选文本及实际语言。
- 正常播放需要会话内执行位置和叙事记录；第一阶段不要求将其持久化。

### 4.2 待确认的数据契约

AST 节点集合、独立控制流表示、选项标签本地化、说话人标识与显示名、源位置、呈现标识、完成事件均待工程讨论。

不在行为规则确定之前写出具有误导性的完整接口。工程文档中的候选字段不自动成为本节规范。

## 5. 运行时与接入

### 5.1 术语边界

| 术语 | 含义 |
| --- | --- |
| 原始点击 | 来自玩家的输入；不等同于播放器必然收到 `next` |
| 快速显示全文 | 表现层完成当前句文字呈现的操作，不是核心推进操作 |
| 文本就绪 | 接入层判定的呈现状态，不是 Ktory 核心状态 |
| `next` | 接入层作出推进决定后发送给播放器的信号；核心不再检查文字呈现进度 |
| 演出推进条件 | 游戏侧判断的条件，不要求等同于演出结束 |

### 5.2 文本呈现与推进契约（E01，已确认部分）

1. Ktory 向接入层提供当前内容及相关声明；呈现采用何种效果不属于核心协议。
2. 接入层处理原始点击，并依据自身呈现状态决定快显、忽略或发送 `next`。
3. 快显完全由表现层执行，不要求 Ktory 更新执行位置或获知快显完成。
4. 接入层判断文本是否满足推进条件；核心不维护文本 `canAdvance`，不要求接入层回报文本就绪后才允许推进。
5. 收到 `next` 时，核心按剧情控制流处理；不读取文字播放百分比、不等待文字动画。当前需要选择时，普通 `next` 不推进，必须提交选项才能解除选择造成的推进限制，见 §5.2.1。

原版 §5.3 的“核心异步等待 PresentTextAsync 完成后再检查文本门控”不作为新实现契约。接入层内部可以使用异步技术，但呈现任务的完成不成为核心推进的前置回调。

原版的表现解耦原则在此得到具体落实：声明文本播放策略不等于核心执行该策略。快显点击是否同时请求推进等表现输入策略也由接入层实施，默认交互规范如有需要另行确认。

### 5.2.1 选择提交

- 普通推进与选择提交是不同操作。选择菜单出现后，核心处于需要选择的结构状态；普通 `next` 不能绕过该状态。
- 接入层向播放器提交选项，由播放器决定对应分支。选项呈现和输入方式仍属于表现层。
- 只有收到有效选项才能解除这一选择状态；错误选项的具体错误返回协议待定。
- 该限制来自未确定的剧情分支，与文字是否显示完的表现门控不同。解除当前选择状态不保证后续节点一定可普通推进，例如后续仍可能是另一个选择。

**选择提交包含一次继续执行。** 不要求宿主先提交选择再额外调用 `next`。有效提交后，播放器沿所选分支执行到下一处内容输出、选择或结束位置；不自动越过新输出的第一句。无文本指令拍也构成一次输出／停止位置，见 §2.4。

接入层不能再为同一次选择附加一个普通 `next`，否则可能越过新内容。若需先播放选项确认动画，接入层先记录选择意图，动画结束后再提交；播放器不等待该动画，也不需要暴露“已提交但尚未执行”的中间状态。

### 5.2.2 尚待确认的相邻契约

- `.next(waitTime)` 的显示后计时已确认；接入层标准约定及快显与停留的组合规则已确认，见 §2.3.1；完整参数默认值及无文本节点的适用方式待定。
- 重复／过期推进和选择输入的识别与处理。
- `#AUTO` 区域内自动请求 next 的来源与投递顺序，以及嵌套和跨块作用域，需与基础执行契约一并冻结。

### 5.3 Unity 接入

第一阶段实现基础对话框、立绘与输入接入。其执行和文本选择应遵循本规格。演出相关的门控策略属于游戏侧，但首阶段无需开发完整配置工具。

### 5.4 独立试读

1. 不依赖 Unity，至少提供语言选择。
2. 执行基础行为，跳过不能解释为基础行为的内容，不要求外部状态模拟。
3. 对无法求值的外部选项条件，忽略条件并展示全部选项，供作者选择；不自动执行所有分支。
4. 试读的宽松行为不改变真实游戏中的条件语义，也不证明外部演出正确。

基础行为清单、未知插值与行内条件的展示规则、语法错误处理尚未确认；不据此增加模拟系统。

## 6. 综合场景用例与开发验收断言

### 6.1 用例一：多语言回退与标签确认

```ktory
主角:
  @zh: 这里真冷。
  .emotion(shiver)
```

* **测试前提**：文件 `defaultLang = "zh"`。播放器请求语言设置为 `"en"`。
* **断言结果**：
  1. 输出 `TextPayload.Content == "这里真冷。"`。
  2. 输出 `TextPayload.ActualLanguage == "zh"`。
  3. 输出 `TextPayload.RequestedLanguage == "en"`。
  4. 绝不输出任何伪造的缺译占位符。

---

### 6.2 用例二：选项提交流程与首句停顿

```ktory
#choice
  * [调查房门]
    主角: 门已经被人从外面反锁了。
    主角: 看来只能另找出口。
  + [放弃] -> break

主角: 接下来怎么办？
```

* **测试前提**：核心推进至 `#choice`。状态变更为 `ExecutionStatus.AwaitingChoice`。
* **执行动作**：宿主调用 `SubmitChoice("调查房门")`。
* **断言结果**：
  1. 核心状态变更为 `SuspendedAtBeat`。
  2. 核心派发第 1 句台词载荷：“门已经被人从外面反锁了。”
  3. 核心指针停留在第 1 句，**绝不自动穿过**至第 2 句。
  4. “调查房门”项在会话消耗集合中被记录，再次进入该 choice 时该项置灰或标记为已读。

---

### 6.3 用例三：文字快显与自动步进倒计时时序

```ktory
主角: 这是一句需要测试呈现倒计时的重要线索。
  .skippable(true)
  .next(2)
```

* **时序与断言验证**：
  1. **T=0s**：表现层启动打字机，文字逐字输出。核心处于 `SuspendedAtBeat`。
  2. **T=0.5s（未打完）**：玩家点击屏幕。表现层捕获该输入，瞬时将整句文本全部排印在屏幕上（快显生效）。表现层**严禁**在此时向核心发送 `Step()`。
  3. **T=0.5s 时刻**：由于显示已完成，表现层启动 2.0 秒倒计时（计划于 T=2.5s 触发）。
  4. **T=1.2s**：玩家再次点击屏幕。表现层判定文字已显示且处于等待阶段，**立即取消未触发的 2 秒计时器**，向核心发送 `Step()`，核心推入下一拍。新的一拍绝不会在 T=2.5s 时被残余计时器误触发推进。

---

### 6.4 用例四：Hub 循环调查与 Break 机制

```ktory
=== Room_Investigation ===

#choice.loop
  * [查看书桌]
    #do .sfx("paper")
    主角: 桌上有一张泛黄的日记碎片。
  * [检查窗户]
    主角: 窗户被铁栅栏焊死了。
  + [尝试撞门]
    主角: 门纹丝不动，撞得肩膀生疼。
  + [放弃思考] -> break

主角: 我们离开这里吧。
```

* **断言结果**：
  1. 选择 `[查看书桌]` 并提交：核心进入内联分支，首先停留在 `#do` 独立指令拍，等待一次 `Step()` 后输出台词“桌上有一张...”。台词执行完毕后，控制流根据 `.loop` 重新激活当前 `#choice`。
  2. 再次激活菜单时，`[查看书桌]` 标记为已消耗，其余三项仍可点击。
  3. 选择 `[放弃思考]` 或宿主外部发送 `Break()`：核心跳出循环，直接执行主干后续台词“我们离开这里吧。”
