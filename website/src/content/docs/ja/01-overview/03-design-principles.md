# Ktory の設計原則

**Ktory は、対話を中心とするゲームのための物語制作・接続システムです。** 推奨する制作手順では、本文と物語の流れを `.ktr` に集約します。共通の表示設定、各文での上書き、明示的な演出の受け渡しにより、設定の繰り返しと場面専用コードを減らすことを目指します。

本ページは[設計原則の正本](https://github.com/Kutinana/Ktory/blob/main/docs/ktory-design-charter.md)の要約です。現在のランタイムはホスト駆動で拍ごとに進みます。**共通の既定設定、設定によるリソースの関連付け、明示的な信号依存は、確認済みの目標ですが設計・実装待ちです。構文や API は未確定です。** [実装仕様 §1.4](https://github.com/Kutinana/Ktory/blob/main/docs/ktory-implementation_v1.md#14-2026-09-26-需求修订已确认待落实)を参照してください。製品目標は提供済み機能の一覧ではありません。

## 物語と演出の責任

| 層 | 責任 |
| --- | --- |
| `.ktr` とコア | 推奨手順では本文、セリフの順序、選択肢、分岐を脚本で管理。コアは制御フロー、セッション履歴、言語選択、修飾子の通知を担当 |
| ホストと演出ツール | ゲーム状態、リソース制作、アニメーションと音画の表示、時計、入力、実際のイベントの判定と報告 |
| 接続ツール（新しい目標） | エディターでリソース・オブジェクト・脚本の宣言を関連付け、受け渡し処理を再利用。依存を保持するモジュールとプロトコルは未定 |

Timeline は再生時機を一時的に管理できますが、後続のセリフや分岐まで引き取ったり、同じ物語の流れを二重管理したりする必要はありません。ホストが個別の節を呼び出す方式も許容しますが、通常の制作で必須とはしません。

**拍（Beat）は論理的な停止点**であり、アニメーションの全工程ではありません。現在はホストが `Step()` で進め、`SubmitChoice()` で選択を確定し、コアは移動・音声・タイプライターの完了を待ちません。この現行の境界は、将来の脚本による明示的な信号依存を永久に禁止するものではありません。

**Forward-only** は外部の副作用を自動で取り消さないという意味です。前へのジャンプ、ループ、呼び出しは可能で、将来の復元機能は別途設計します。

## 確認済み・実装待ちの制作目標

共通設定には名前の多言語対応、既定の会話枠、既定の音や音グループ、表情リソースの対応を含め、各文には変更点だけを書くことを目指します。名前とリソースは分けて管理し、必要に応じて関連付けられます。完全なゲームキャラクター実体にまとめる必要はありません。現在の `@speaker` は名前と別名のみを提供します。

表情の省略規則は **現在の文 → 適用される全体の既定値 → 表情を表示しない** です。前の文の局所設定は引き継ぎません。非表示はタグを省くだけでなく、古い表情を実際に消す必要があります。この動作は実装待ちであり、BGM の省略を音楽停止と解釈する規則ではありません。既定値の明示的な解除、誤ったリソースの扱い、共通定義のスコープは未定です。

脚本は、後続の物語が演出の特定ノードや完了信号に依存することを、セリフのない区間も含めて宣言できるべきです。実際のイベントはホストが判定・報告します。依存の保持場所、通知の照合、クリックやスキップとの組み合わせは未定です。時間の要求には時間、イベントの要求には信号を使い、「完了後に続ける」場合は完了信号を優先します。現行の `.wait(t)` は単独で自動進行しない最低待機時間であり、`.next` の規則も変わりません。すべての演出が既定で進行を止めるわけではありません。

作者はエディターでリソース、オブジェクト、宣言を関連付けます。新しい種類の能力には一度の接続実装が必要でも、同じ能力を使う場面の追加は主に内容と設定で行い、監視・停止・再開・解除処理の繰り返しを減らします。意味のあるノードは演出制作者が配置し、汎用イベントも拡張手段として残します。すべての動作がコード不要になるという約束ではありません。

## Ink との関係

[Ink](https://github.com/inkle/ink/blob/master/Documentation/RunningYourInk.md) はホストからの進行、選択肢、タグ、外部関数、プロジェクト独自のラッパーをすでに利用でき、[Unity 統合](https://github.com/inkle/ink-unity-integration)には接続と試読の機能があります。Ktory はセリフ表示、リソースの関連付け、受け渡しの規約を再利用可能な製品機能として維持する方針です。Ink では不可能だという意味ではありません。製品価値は作業量の削減で検証し、独自ランタイムの必要性は意味規則と保守コストから判断します。

## 現段階と検証

第 1 段階は引き続きセリフ、選択肢、同一ファイルの訳文、独立試読、Unity の基本表示が中心です。新目標によって完全な Timeline 統合、永続セーブ、ボイス、訳文の抽出・取込、他エンジン対応は追加しません。現在の状況に応じた物語の選択、プレイヤーに操作を返した後の物語再開は、確認済みですが延期した要求です。タスクシステムや汎用ゲーム状態機械には拡張しません。

試読で未知の演出を省略しても、信号が発生したことにはなりません。新しい受け渡し点の通過や手動確認の方針は別途定めます。表情が残らないこと、逐文修正を要しない共通設定、関連付けの再利用、尺の変更に左右されない完了依存、脚本に現れる受け渡し変更、古い通知の拒否を検証します。コア試験と試読は実際の Unity 演出の検証を代替しません。
